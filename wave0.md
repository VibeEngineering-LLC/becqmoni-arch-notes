# Волна 0: дефекты, дающие неверные числа сегодня

Реестр для передачи автору BecqMoni. База: ветка roi-wizard-reworked, коммит **d80c7ee** (при переносе на master номера строк потребуют пересчёта). Каждый пункт проверен прямым чтением кода или поставочных конфигов; ни один не требует смены модели данных.

Порядок — по тяжести последствий для пользователя.

## A. Продукт не работает из коробки

**A1. Библиотечный фит не стартует никогда на свежей установке.**
Поставочный `config/NuclideDefinition.xml` — 77 записей, ноль тегов `Sets`, ноль `IsAnchor`, ноль `Intencity`. Гейт `LibraryPeakFitter.cs:480` фильтрует линии по членству в наборе, `:483-485` требует хотя бы один якорь — при пустых `Sets` фит выходит сразу.
*Оговорка:* миграция существующих установок требует `FormatVersion` в `NuclideDefinitionFile` (пункт 1 arch-документа), поставочный `config/` копируется только при отсутствии каталога (`MainForm.cs:102-103`).

**A2. Активность считается по чужой кривой эффективности — по умолчанию, у всех.**
`EfficencyROIGuid` не проставлен ни в одном из 9 файлов `config/device/*.xml`. `DocEnergySpectrum.cs:451-457`: при отсутствии Guid берётся `ROIConfigList[0]`, `:459` записывает этот Guid в документ. Список отсортирован по `LastUpdated` (`ROIConfigData.cs:213`), то есть `[0]` — произвольный конфиг; на свежей установке это `Obsidian Marinelli 0.5.xml` — файл с дефектом A3. Запись Guid в документ делает подмену необратимой.

**A3. Узел кривой с физически невозможной эффективностью.**
`config/ROI/Obsidian Marinelli 0.5.xml:59-61`: `Energy=20`, `Efficiency=1471.85`, `ErrorPercent=554` при остальных 149 точках в диапазоне 2,8·10⁻⁵…5,6·10⁻³. ε > 1 невозможна; монотонный сплайн утаскивает левый край кривой.

## B. Молчаливые нули и подмены

**B4. Области, созданные мастером, дают нулевую активность.**
`RoiWizard/SetExporter.cs:51-60` заполняет Name/Enabled/PeakEnergy/границы/Color/HalfLife/Intencity, но не `BecquerelCoefficient`. Расчёт `MeasurementResultManager.cs:48` умножает на 0.

**B5. Тихий нуль K неотличим от «не посчитано».**
`ROIConfigForm.cs:951` требует `HasEfficiency && Intencity > 0`, `:955` — `effData != null && Efficiency > 0`; при провале любого условия K остаётся дефолтным 0 без статуса. Живой репродьюсер в поставке: `config/ROI/Ra-226 Intensities.xml` — 16 областей с заполненными интенсивностями и K=0 (то же в `Th-232 Intensities.xml` — 11 областей). Сюда же ветка `Utils/ROIAriphmetics.cs:28-31`: запрос ε вне `[MinEnergy, MaxEnergy]` возвращает null, вызывающий код молча пропускает расчёт.

**B6. Ссылка между областями резолвится по имени.**
`MeasurementResultManager.cs:372-386`: первая область с совпавшим именем, `break`. При дубле имён вторая недостижима — в поставке это реально: две области «Co60» (1172 и 1332 кэВ) в `Cs134,Cs137,K40.xml`, одиннадцать областей «Ra-226» в `Ra226 + K40.xml`. При отсутствии совпадения цикл проходит вхолостую и netCounts остаются нулями без сообщения.

**B7. Одиннадцать областей с одинаковым коэффициентом.**
`config/ROI/Ra226 + K40.xml`: 11 из 12 областей несут `BecquerelCoefficient=290`. Разные линии Ra-226 с разными ε и I не могут иметь один K — похоже на копирование значения.

**B8. Удельная активность считается «на 1 кг» у не вводивших массу.**
`SampleInfoData.cs:121,124`: `weight = 1.0`, `volume = 1.0` — «не введено» неотличимо от «ровно 1». Комментарий `MeasurementResultManager.cs:75-76` «Weight defaults to 0 — guard the denominator» не соответствует фактическому дефолту, гард не срабатывает.
*Оговорка:* полное решение требует nullable-семантики полей (правка формата); в Волне 0 закрывается сообщением вместо тихого счёта.

## C. Доза

**C9. Падение при нелинейной калибровке.**
`DoseRateManager.cs:32` — безусловный каст `(PolynomialEnergyCalibration)`; `NonlinearEnergyCalibration` — сестринский класс (оба от `EnergyCalibration`), штатно сериализуется (`DeviceConfigInfo.cs:246-247`). Результат — `InvalidCastException` в тике таймера.

**C10. Показание дозы зависит от режима отображения графика.**
`MainForm.cs:639-641` передаёт `BackgroundMode` из вида спектра; `DoseRateManager.cs:23-31` при `Substract` и наличии фона вычитает его, иначе считает по сырому. Переключение галки отображения меняет цифру дозы. Отдельно: при `Substract` без загруженного фона расчёт молча идёт по сырому спектру — индикатор режима и факт расходятся.

**C11. Двойной учёт граничного канала.**
Калибровка `DeviceConfigForm.cs:2550` — `j < toChannel`; применение `DoseRateManager.cs:58` — `i <= endch`, при `UpperBound[i] == LowerBound[i+1]` канал стыка учитывается дважды.

## D. Отрисовка и служебное

**D12. Одна плохая область гасит отрисовку всех последующих.**
`EnergySpectrumView.cs:2879` `ShowROIBorderLine`, обработка `:2906-2909`: `catch (OutofChannelException) { break; }` — цикл по областям прерывается (при этом верхняя граница в соседней ветке клампится, асимметрия).

**D13. Масштаб маркеров строится по всем областям.**
`EnergySpectrumView.cs:2812`: условие `roidefinitionData.Intencity < 100.0 || roidefinitionData.Intencity > 0.0` — дизъюнкция истинна при любом значении, фильтр не фильтрует.

**D14. Фоновый спектр разделяется между экземплярами.**
`ResultData.cs:351-352` — копирование по ссылке (`this.energySpectrum = old.EnergySpectrum`, `this.backgroundEnergySpectrum = old.BackgroundEnergySpectrum`), тогда как парный конструктор `:386-387` делает глубокую копию обоих.

**D15. Исключение при удалённом конфиге EasyControl.**
`MainForm.cs:2670`, `:2680` — прямая индексация словаря без проверки ключа: `KeyNotFoundException`, если конфиг, на который ссылается EasyControl, удалён.

## Как проверять

Числовые последствия A1–C11 фиксируются прогоном корпуса `tools/LibraryFitLab` (69 спектров, 23 группы детекторов) до и после правки: каждый закрытый дефект получает запись «что изменилось в числах», расхождения вне этого списка считаются регрессией. D12–D15 проверяются вручную.
