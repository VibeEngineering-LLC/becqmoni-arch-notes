## 1. Назначение, источники ядерных данных, состав поставки

**Назначение.** Программа для получения информации о параметрах радиоактивного распада «более 3000» радионуклидов (с учётом метастабильных состояний) и формирования пользовательских библиотек линий нуклидов в формате комплекта программ ЛСРМ — файлы `.lib` [NM с.5, §1].

**Источники ядерных данных** (комплект поставки, §2.4.10) [NM с.36]:

1. **ENSDF** — источник по умолчанию; данные ENSDF с сайта Брукхейвенской лаборатории по всем линиям, **кроме рентгеновских, которые берутся из TOI** (Table of Isotopes);
2. **LSRM** — собственные данные ЛСРМ по U-235;
3. **DDEP** — данные лаборатории Анри Беккереля (Decay Data Evaluation Project, nucleide.org);
4. **SRD** — стандартные справочные данные (ССД), утверждённые Росстандартом (свидетельство № 273 от 31 октября 2013 г.);
5. **JEFF** — Joint Evaluated Fission and Fusion File (OECD NEA).

Дополнительно: база **EGAF** МАГАТЭ (Evaluated Gamma-ray Activation File, www-nds.iaea.org/pgaa/) по мгновенному нейтронно-активационному гамма-излучению — отдельная база `PromptGamma.mdb` [NM с.28, 48]. Атомные массы — из оценки Ame2003 (G. Audi, A. H. Wapstra, C. Thibault, Nucl. Phys. A729 (2003) 337; таблица с cdfe.sinp.msu.ru) [NM с.10, §2.3.2]. Пользователь может создавать собственные источники данных (правки нуклидов/линий сохраняются в БД с именем источника) и сравнивать значения линии по нескольким источникам [NM с.36–38, §2.4.10].

**Хранение данных** — база MS Access `NuclideMaster.mdb` (подключение через `NuclideMaster.udl`); предусмотрено штатное сжатие БД средствами MS Access [NM с.45–46, §3.2; с.48, §4]. Версия базы отображается в настройках (вкладка «База данных», кнопка «История версий») [NM с.43]; по истории версий программы БД доводилась до версии 9.26 (сборка 2.10.1465) [VH].

**Состав поставки (рабочая директория)** [NM с.48, §4]:

- `NuclideMaster.exe` — основная программа;
- `Databases\` — `NuclideMaster.mdb` (параметры распада), `PromptGamma.mdb` (EGAF), `Containers.mdb` (транспортные контейнеры);
- `Data\` — библиотеки пользователя; в поставке пример `ОСГИ.lib`;
- `CNLUtility\CNLUtility.exe` — утилита сравнения библиотек;
- `Container\` — утилиты контроля источника/упаковки и расчёта коэффициентов ослабления (`Containers.exe`);
- `XRay_Viewer\XRay_Viewer.exe` — просмотр/редактирование БД рентгеновских линий;
- `Spectrometer\` — опорные спектры, кривые эффективности, пики-образы для генерации спектров;
- `Doc\`, `Temp\` (журнал), `NuclideMaster.ini`, `NuclideMaster.udl`, `Uninstall.exe`.

**Защита электронным ключом** (dongle): без ключа — Demo-режим, в котором схема распада строится только для Np-237, Th-232, U-238, U-235, Cs-137, а построение графиков и генерация спектров недоступны. Функции по ключу: Decays, Graphics, Spectra, Factors (последняя — расчёт поправок на истинное суммирование и эффективности методом Монте-Карло, Nuclide Master Plus) [NM с.6, §2.1; с.46, §3.4]. Языки интерфейса: русский и английский [NM с.5].

## 3. Возможности поиска

### 3.1. По нуклиду

- Поле «Поиск нуклида» — поиск по названию в общем списке [NM с.9, §2.3.1].
- Фильтрация общего списка: по названию, атомному номеру (массовому числу), заряду, минимальному периоду полураспада; отображение/скрытие/подсветка цветом стабильных, метастабильных и нуклидов без данных о T½ [NM с.9].
- Сортировка: по имени, периоду полураспада, атомной массе (клик по заголовку столбца или контекстное меню; повторный клик — обратный порядок) [NM с.9–10].
- Альтернативные способы выбора: электронная таблица Менделеева (снизу — изотопы элемента с цветовой кодировкой типа распада α/β−/β+ и скорости распада) [NM с.29–30, §2.3.9]; карта нуклидов в осях A–Z с всплывающей информацией и списком метастабильных состояний [NM с.30–31, §2.3.10]; окно «Поиск родителя» — переход к любому родителю по цепочке [NM с.29, §2.3.8]; список всех родительских и дочерних с модами и вероятностями распадов (из карты нуклидов) [NM с.31].

### 3.2. По энергии линии (идентификация)

Окно **«Поиск близких линий»** (меню Нуклид → Идентификация линии, кнопка панели или контекстное меню библиотеки) [NM с.41–42, §2.4.13; с.77, §5.25]:

- поиск **в пределах окна идентификации**: поля «Энергия линии, кэВ» + «Окно идент., кэВ» (энергия по умолчанию 100 кэВ или берётся из выделенной в библиотеке линии);
- либо поиск **в диапазоне энергий** (поля «Диапазон, кэВ» от–до);
- область поиска: текущий нуклид / **все нуклиды БД** / включать дочерние по цепочке / включать родительские по цепочке;
- результат: энергия ± неопределённость, интенсивность ± неопределённость, тип линии, лоренцево уширение, индекс в БД, нуклид-владелец;
- **сортировка** результатов — контекстной командой «Сортировать»: по атомному номеру или по энергии;
- дополнительная **фильтрация результатов**: по периоду полураспада (T<=, T>= с единицами) и по абсолютной интенсивности (I<=, I>=);
- найденную линию можно сразу добавить в формируемую библиотеку (контекстное меню «Добавить линию в библиотеку»).

Родственный механизм — **индексация линий** (для библиотек формата 2.0): однозначная привязка линии библиотеки к линии БД по уникальному индексу вида `Eu-152_70` вместо идентификации по энергии в окне; окно «Добавление индексов линий из БД» ищет совпадения по энергии в пределах неопределённости, с опциями «Линии с дочерними», «Линии с одинаковым типом», «Задать неопределённость энергии»; поддерживается соответствие «одна линия библиотеки — несколько линий БД» (для объединённых линий) [NM с.39–41, §2.4.12].

### 3.3. По типу излучения

- Типы линий в библиотеке: **G** — гамма, **X** — рентген, **A** — альфа; в списке линий схемы распада дополнительно **An** — аннигиляционная [NM с.10, §2.3.2; с.13, §2.3.3.2]. В форматах файлов 1.6/1.7 предусмотрены также **B** — бета и **D** — доплеровски уширенная линия [NM с.51–52, §4.1.3–4.1.4].
- Переключение отображения «Альфа линии / Гамма линии» на вкладке «Линии» схемы распада; для гамма-выборки — флаги G-линии/X-линии (включение/отключение рентгена) [NM с.14, §2.3.3.2].
- Тип линий, добавляемых в библиотеку (альфа или гамма), задаётся в настройках [NM с.43, §3.1].
- Фильтрация линий в библиотеке: по энергии (диапазон, кэВ) и по интенсивности (абсолютная либо относительная — в % от самой сильной линии нуклида); отфильтрованные линии помечаются как невыделенные и/или неучаствующие в обработке (символ `n` в `.lib`) [NM с.33, §2.4.4].
- Для рентгеновских линий опционально показываются подтип (KA1, KA2, KB и т.д.), дочерний нуклид и лоренцево уширение K-линий из TOI [NM с.10, 32, 43].

### 3.4. Цепочки распада

Окно «Схема распада» (по нуклиду) [NM с.11–13, §2.3.3]:

- вкладка **«Схема распада»** — графическая схема в координатах A–Z: каждый нуклид — прямоугольник с названием, T½, вероятностью, направлением и типом распада; наиболее вероятная ветвь выделена жирными стрелками; для текущего нуклида справа — заряд, T½, вероятность, спин/чётность, типы распада; пункт «Схема подробнее…» раскрывает метастабильные состояния с вероятностями заселения;
- вкладка **«Цепочка распада»** — та же схема в виде дерева (выбранный нуклид — синяя иконка, наиболее вероятная ветвь — зелёные);
- вкладка **«Линии»** — сводная таблица всех линий всех нуклидов цепочки (тип A/G/X/An, нуклид, энергия ± неопр., интенсивность ± неопр., отн. неопр. %); фильтрация по нуклидам, диапазону энергий, диапазону интенсивностей, «> % от Imax» (по нуклиду или по всем линиям цепочки), типам G/X.

**Равновесная нормировка на родителя — есть**: флаг **«Пересчет интенсивности на заданное время»** пересчитывает интенсивности всех линий цепочки с привязкой к активности родительского нуклида (задаются дата аттестации и дата измерения; кнопки Пересчитать/Восстановить) [NM с.15, §2.3.3.2]. Полученный набор добавляется в библиотеку кнопкой «Добавить с привязкой к активности родительского» — один родительский нуклид с пересчитанными линиями; для распадов на (через) метастабильные уровни добавляются данные **в равновесном состоянии** [NM с.28, §2.3.7]. Время пересчёта по умолчанию — настройка «Время для пересчёта линий дочерних, лет» [NM с.43].

Расчёты по цепочке: активности и числа ядер дочерних на заданное время (окно «Активность на время Т») [NM с.18, §2.3.3.4]; график изменения активностей (2D/3D) [NM с.24, §2.3.5]; анимированная гистограмма активностей/чисел ядер/масс с поиском времени насыщения и обратным пересчётом активности на прошедшую дату [NM с.25–27, §2.3.6].

## 4. Какие данные показываются по нуклиду

- **Нуклид**: название, период полураспада (сек/мин/час/сут/лет; «стабилен»/«нет данных»), гамма-постоянная (Р·см²/(ч·мКи), считается по линиям выше настраиваемого порога энергии, аннигиляционная линия учитывается), тип нуклида (пользовательская метка: медицинский/ядерный/естественный/фоновый/вспомогательный/prompt-gamma), атомная масса ± неопределённость (Ame2003) [NM с.10, §2.3.2].
- **Линии**: энергия, кэВ ± абс. неопределённость; интенсивность ± абс. неопределённость (в т.ч. ENSDF-коды LT/GT/LE/GE/AP/CA/SY); тип (G/X/A); подтип рентгеновской линии и дочерний нуклид; лоренцево уширение K-линий (эВ, из TOI); флаг участия в обработке; индекс линии в БД; комментарий [NM с.10, §2.3.2].
- **Распад**: вероятности, моды, спин и чётность (JPI) — в схеме/цепочке распада [NM с.12, 68–69].
- **Схема уровней (схема переходов)** — есть: окно «Схема переходов <нуклид> → <дочерний>» — графическое изображение альфа-, бета-, гамма-переходов со списком энергетических уровней дочернего нуклида (энергия уровня, спин, чётность); толщина линии перехода пропорциональна интенсивности; масштабирование по оси энергий; фильтр по минимальной интенсивности [NM с.15–16, §2.3.3.3]. Табличный вид — окно «Список переходов, уровней и линий»: для гамма — уровни «с/на», энергия перехода, интенсивность перехода, интенсивность излучения, **коэффициент конверсии**; для альфа/бета — энергия и интенсивность перехода [NM с.16–17]. Окно «Список возможных гамма-переходов» — гипотетические переходы между всеми парами уровней, отсутствующие в ENSDF, с подсветкой [NM с.17–18].
- **Родители/дочерние**: списки с T½, модами и вероятностями распадов [NM с.29, 31].
- **Расчётные величины**: активности и числа ядер по цепочке на время T, время насыщения, генерируемые альфа-/гамма-спектры [NM с.18–27].

## 5. Экспорт и форматы

**Основной экспорт — библиотеки `.lib`** для пакета SpectraLineXX (SpectraLineAda и др.) [NM с.5, §1]:

- **формат 2.0** (по умолчанию) — XML (кодировка windows-1251): секция `Library` (library_type, library_version, database_version), `Comment`, секции `Nuclide` (name, half_life_value/unit, gamma_constant, atomic_mass, d_atomic_mass, nuc_type, nuc_num, with_daughter, daughter_recalculation_time, source) и `Line` (energy, d_energy, intensity, d_intensity, line_type, dbid — индекс в БД, comment, used, enabled, width, xline_type, xray_child_nuclide, source). Поддерживается SpectraLine ≥ 1.7 [NM с.52–53, §4.1.5];
- **формат 1.7** — текстовый: заголовок `<LSRM Nuclide library Version=1.7>`, строка нуклида (название, T½ с единицей в скобках, гамма-постоянная, атомная масса ± неопр., [типы нуклида M/N/E/B/A/P]), строки линий (энергия, неопр. энергии, интенсивность, неопр. интенсивности, тип A/B/X/D, признак `n` — не участвует в обработке, `LW<число>` — лоренцево уширение, `;комментарий`); закомментированная линия начинается с `;` [NM с.51–52, §4.1.4];
- исторические форматы 1.0, 1.5, 1.6 — описаны в §4.1.1–4.1.3 [NM с.48–51].

При сохранении записываются **только нуклиды и линии, отмеченные флажками**; опциональные проверки перед сохранением: одинаковые энергии (объединение), нулевые интенсивности (удаление), пересчёт ENSDF-кодов в числа [NM с.7, §2.2.4].

**Обмен со SpectraLine через буфер обмена**: «Скопировать в буфер обмена» / «Вставить из буфера обмена» — нуклид, линия или целая библиотека (открывается вкладкой «From SpectraLine») [NM с.42, §2.5].

**Генерация спектров** (по ключу): суммарный альфа- или гамма-спектр списка нуклидов на заданное время набора с учётом всей цепочки распада; результат — файл **`NM.spe`**, автоматически открываемый внешней программой обработки (SpectraLine) командной строкой `<exe> NM.spe|<конфигурация>`. Для гамма — используются `.cnf`-конфигурация SpectraLine, опорный спектр `.spe`, фон `.spe`, кривая эффективности `.pol`/`.efa`, пик-образ `.cpt`, файл расстояний до эффективного центра детектора `.txt`; расчёт для точечного источника (расстояние до крышки детектора) или источника в транспортном контейнере (утилита Containers.exe, учёт поглощения). Для альфа — опорный спектр, фон, пик-образ и эффективность регистрации в % [NM с.19–24, §2.3.4].

Прочие «выходы»: пользовательский источник данных в БД на основе библиотеки [NM с.36]; журнал событий `Temp\NuclideMaster-<дата>.TXT` [NM с.46]. Экспорт в универсальные табличные форматы (CSV/Excel) в руководстве не описан (см. раздел 9).

## 6. Чем Nuclide Master Plus отличается от базовой версии

Plus — **расширенная версия**: к базовой функциональности добавляется программа **EffCalcMC** (Efficiency Calculation Monte-Carlo) — расчёты методом Монте-Карло для полупроводниковых и сцинтилляционных детекторов в точечной, цилиндрической, конической геометрии и в сосудах Маринелли [NMP с.4, §1]. Функция защищена позицией ключа «Factors» [NM с.46, §3.4]. Три режима:

1. **Расчёт эффективности регистрации** [NMP с.5–9, §2.1]: геометрия+детектор (модели из GMaster: коаксиальный/колодезный/сцинтилляционный детектор; источник точечный/цилиндр/Маринелли/конус), сетка энергий (линейная/логарифмическая, Emin–Emax, N точек; либо загрузка из `.enx` ENSDF-формата), расчёт с заданным числом испытаний; вывод: эффективность ± отн. неопр. %, опционально удельная (на массу) и полная эффективность; просмотр в утилите Efficiency; сохранение в файл **`.efr`** (секция `<детектор>;<геометрия>;EfReg`).
2. **Расчёт поправок на истинное (каскадное) суммирование** [NMP с.9–13, §2.2]: для произвольного нуклида из БД (в т.ч. по цепочке, с дочерними, во все геометрии сразу), опция учёта X-линий; расчётное ядро — `TCCFCALC.dll` (утилита TccfCalc, использует файлы ENSDF/2, ECCBINDX.BIN, ICC.BIN) [NMP с.26, 29]; сохранение в библиотеку поправок **`.tc`** (+ попутно эффективности в `.efr`); дополнение существующих `.tc`; **коррекция значений энергий** старых `.tc`-библиотек, созданных по ENSDF/2, под энергии текущей БД (поиск в пределах неопределённости, с дочерними, цветовая индикация точное/в пределах/не найдено) [NMP с.12–13, §2.2.7].
3. **Генерация спектров методом Монте-Карло** [NMP с.13–19, §2.3]: геометрия + детектор + **модель анализатора** (тоже из GMaster); список нуклидов с активностями, датами пробоотбора и измерения; суммарный спектр нескольких нуклидов; опция «Расчёт спектров с суммированием» (истинное суммирование каскадов); спектр сохраняется и открывается в программе обработки.

Настройки Plus [NMP с.23–24, §3]: пути к БД `Detectors.mdb`, `ObjectsModels.mdb`, `Materials.mdb`, `NuclideMaster.mdb` (или `.udl`); директории `.din`/`.sin`-файлов моделей; автозапуск Efficiency и программы обработки спектров; **учёт электронного транспорта**; расчёт полной эффективности; число одновременно рассчитываемых нуклидов; настройки хранятся в `EffCalcMC.ini` [NMP с.26–27, §4.1]. Efficiency берётся из установленного SpectraLine (Ultimate → Handy → BG → GP по очереди), иначе из дистрибутива [NMP с.23].

Отличие в генерации спектров: базовая версия строит спектр **из опорного спектра, кривой эффективности и пика-образа** (полуэмпирически), Plus — **полноценным Монте-Карло по модели детектора/геометрии/анализатора**, с каскадным суммированием и электронным транспортом.

## 7. Сопутствующие программы (по абзацу)

**GMaster** — модуль создания моделей спектрометров и лабораторных геометрий: моделирует детекторы (полупроводниковые коаксиальные и колодезные, сцинтилляционные — с полным набором размеров: кристалл, отверстие, мёртвые слои 1–5, упаковка, крышка, рассеиватель — и материалами конструкционных элементов), анализаторы, коллиматоры и источники; модели сохраняются в базы данных (`Detectors.mdb`, `ObjectsModels.mdb`) или в файлы `.din`/`.sin`; есть проверка размеров источника, просмотр/правка содержимого БД, редактор материалов; интегрирован с EffMaker и Nuclide Master Plus (вызывается кнопками «Новая»/«Редактировать» из EffCalcMC) [GM с.6 (§1), 6–7 (§2.1.1), содержание с.5; NMP с.5–6].

**XRayViewer** — просмотр и редактирование базы данных рентгеновских линий `X-ray.mdb`: двухуровневый список «элемент (название, заряд) → линии (название линии, энергия, интенсивность ± абс. погрешность)»; добавление/правка/удаление элементов и линий (окно «Правка» или F2 в списке); изменения виртуальны до команды Файл → Сохранить/Сохранить как; настройки — путь к `.mdb` и директория языковых файлов; RU/EN интерфейс [XR с.4–9].

**Efficiency 1.7** — утилита расчёта эффективности регистрации и построения аппроксимирующей кривой (входит в SpectraLine, запускается и автономно с ограниченной функциональностью): расчёт по файлу эталонных источников (паспортов) или с ручным вводом, абсолютным и относительным методами; аппроксимирующая кривая по нескольким зонам; фильтрация результатов; коррекция K-края; пересчёт эффективности на плотность материала; слияние файлов эффективности; импорт `.ecc` (ISOCS Canberra), `.txt`, `.csv`; работает с файлами `.efr` (данные) и `.efa` (кривая) [EF с.5–8 (§1–2), содержание с.3].

**Сравнение библиотек (CNLUtility)** — сравнение и редактирование библиотек радионуклидов: два `.lib`-файла, два источника данных БД Nuclide Master (по одному нуклиду) или библиотека против источника; критерии — наличие нуклида (по имени), наличие линии (по энергии — точно или в пределах √(суммы квадратов неопределённостей), либо по индексам линий), совпадение всех параметров; различия подсвечиваются цветом, навигация по различиям, синхронизация списков; вердикт «библиотеки различны/идентичны» в статусной строке; поддерживается формирование библиотеки: правка (F2), копирование/перемещение нуклидов и линий между сторонами, сохранение в `.lib` [LC с.4–8].

## 9. Не нашёл в доках

- **Дата/версия среза ENSDF для текущей базы** — в руководстве не указана; в истории версий упоминаются лишь обновления БД до внутренних версий (9.24–9.26) без даты среза ENSDF; последняя явная привязка к ENSDF — «в соответствии с версией ENSDF от 28.11.2013» для сборки 2.9.474 [VH]. Что лежит в актуальной 9.26 — из документации не следует.
- **Число нуклидов точно** — только формулировка «более 3000 с учётом метастабильных состояний» [NM с.5]; разбивки по источникам (сколько нуклидов в DDEP/JEFF/SRD-наборах) нет.
- **Аттестация/метрологический статус базы** — упомянуто лишь свидетельство ССД № 273 от 31.10.2013 применительно к источнику SRD [NM с.36]; ТЗ, аттестации методик или программы в целом в руководстве не описаны.
- **Экспорт в CSV/Excel/текстовые таблицы** — не описан; единственные машинные форматы вывода: `.lib` (1.0–2.0), `.spe` (генерируемые спектры), `.efr`/`.tc` (Plus), буфер обмена SpectraLine. Печать отчётов также не упоминается.
- **Поиск по энергии среди альфа-линий** — окно «Поиск близких линий» описано без ограничения по типу линии (тип выводится в результатах), но явного фильтра «только альфа/только гамма» в этом окне в руководстве нет.
- **Бета-спектры** — расчёт не предусмотрен (только альфа- и гамма-спектры); бета-переходы видны лишь в схеме переходов; тип линии B существует только в форматах файлов 1.6/1.7.
- **Формулы расчёта активностей по цепочке** (Бейтмана и т.п.) и алгоритм генерации спектра — в руководстве не приведены, описан только интерфейс.
- **PC-Nucl** — не упоминается нигде в прочитанных документах (источники: ENSDF, TOI, DDEP, JEFF, SRD, LSRM, EGAF, Ame2003).
- **Ограничения Demo по спискам линий/библиотекам** — описаны только три защищённые ключом функции (Decays, Graphics, Spectra/Factors); работает ли редактирование библиотек без ключа полностью — явно не сказано (по тексту §2.1 «возможности в полном объёме — только с ключом»).
